# Модерация приложения в Altegio: чек-лист

Партнёрский аккаунт: `2548`, боевой аккаунт ApiPay (контакт `georgy@apipay.kz`,
сайт apipay.kz). Developer company name записан как `ApiPay1` — это только
название поля, отдельного аккаунта заводить не нужно.

**На модерацию идёт приложение `ApiPay.kz`** (статус Not published, тариф
от 10 000 ₸/мес) — оно же «первое» в списке. Приложение `2315`
`apipay_prepay_test` остаётся Non-public как стенд; остальные черновики
удалить, чтобы не путать модератора.

Партнёрский токен один на аккаунт `2548` и при смене приложения не меняется.
Системный user token выдаётся **на приложение** — при переходе со стенда на
`ApiPay.kz` его нужно взять заново из API Access этого приложения.

## 1. Права (API Access)

Итог: **5 прав из 129**. Всё, что не в списке, снято целиком — Booking form,
Settings, Client base, Loyalty, Online booking, Overview, Inventory, Tips,
Reports.

### Digital schedule — 2 из 5

| Право | Зачем |
|---|---|
| Schedule and booking history unlimited access | `GET /record/{company_id}/{record_id}` — услуги и сумма |
| Show phone number | без него телефон клиента в записи скрыт, счёт не выставить |

Снято: Change team member's work schedule, Reschedule appointment,
Show statistics.

### Finance — 3 из 13

| Право | Зачем |
|---|---|
| Cash flow | родитель, без него не включается создание транзакций |
| Creating Transactions | `POST /finance_transactions/{company_id}` — отметка предоплаты |
| Access to accounts and cash register | см. оговорку ниже |

Снято: Editing и Delete transactions, Access to balance, check printing,
daily cashier report, Operations with POS, payroll charts, payroll
calculation, Online payments и Access to editing.

**Оговорка про кассы.** Altegio не пускает приложения маркетплейса к финансам
филиала: `GET /accounts/{company_id}` отвечает «No rights to manage the
location» даже при Finance 13/13 (см. `altegio-findings.md`). Поэтому кассу
салон вводит руками на странице настройки, а право `Access to accounts and
cash register` фактически ничего не даёт. Снимать его тем не менее рано:
неизвестно, не требуется ли оно для `POST /finance_transactions` — запись
проверялась при полных правах. Проверять только вместе со сквозным тестом.

### Клиентская база не нужна

Телефон клиента приходит внутри записи по праву Show phone number.

### Уведомления

Подписка на ресурс `record`, события create и update.

После изменения прав филиал нужно отключить и подключить заново: системный
пользователь получает права в момент подключения.

## 2. Адреса и порядок Non-public → Public

Здесь ловушка, на которой мы потеряли время:

- поле **«Address to send notifications to» видно только у Non-public**
  приложения;
- **Registration Redirect Url срабатывает только у Public**. Пока приложение
  Non-public, Connect подключает салон молча: браузер остаётся в карточке, на
  наш адрес не приходит ничего. Именно это выглядело как «Continue вместо
  Disconnect».

Отсюда порядок: **Non-public → вписать адрес уведомлений → Save → переключить
в Public → подключать салон.**

- Address to send notifications to → `<PUBLIC_BASE_URL>/webhooks/altegio`
- Registration Redirect Url → `<PUBLIC_BASE_URL>/altegio/install`
- Callback Url → `<PUBLIC_BASE_URL>/altegio/uninstall`

Одна пара адресов обслуживает все салоны.

| Галка | Значение | Почему |
|---|---|---|
| Open registration form in iframe | по желанию | добавляет вкладку Settings в карточку приложения; Altegio каждый раз прогоняет свой экран согласия перед нашей страницей |
| Pass user data when connecting the integration | вкл | добавляет `user_data` и `user_data_sign`. Это профиль сотрудника (base64 JSON), **токена там нет** |
| Allow application to be added to multiple locations | вкл | салон подключает все локации разом |

Галкам нужно и сохранение, **и новое подключение** — на уже подключённых
салонах эффекта нет.

## 3. Описание приложения

**Название:** ApiPay.kz — предоплата по записи

**Короткое описание:**
Автоматическая предоплата по записи: клиент получает счёт сразу после записи,
оплата отмечается в финансах филиала.

**Полное описание:**

ApiPay превращает каждую запись в счёт на предоплату и сам отмечает оплату в
Altegio — без ручной сверки и напоминаний. Деньги приходят на ваш собственный
Kaspi Pay: ApiPay выставляет счета поверх него.

Как это работает:
1. Клиент записывается на услугу — приложение сразу выставляет ему счёт на
   стоимость записи.
2. Клиент оплачивает счёт.
3. Оплата автоматически проводится приходом по кассе филиала с комментарием,
   в котором указан номер счёта.

Что нужно для подключения: аккаунт ApiPay с подключённым Kaspi Pay. При
подключении приложение попросит API-ключ ApiPay и номер кассы, куда зачислять
предоплату. Больше ничего настраивать не нужно.

Что это даёт:
- меньше неявок: запись подтверждена деньгами;
- никакой ручной работы администратора — оплата попадает в финансы сама;
- прозрачная сверка: каждая оплата привязана к конкретной записи и визиту.

Приложение запрашивает минимум прав: чтение записей и создание финансовых
транзакций. Данные клиентов никуда не выгружаются и используются только для
выставления счёта по конкретной записи.

**English (short):**
Automatic prepayment for bookings: the client gets an invoice right after
booking, and the payment is recorded in the branch's finances automatically.

## 4. Тариф

Карточка показывает «from 10 000 ₸/mth». В описании нужно явно сказать, что
входит в эту сумму и берётся ли комиссия с предоплаты отдельно: модерация
придирается к карточкам, где цена есть, а за что платят — не написано.

## 5. Скриншоты

Минимум четыре, в одном разрешении, без реальных персональных данных:

1. Карточка приложения / экран подключения — что видит салон при установке.
2. Страница настройки `/setup/<токен>`: поля API-ключа ApiPay и номера кассы.
3. Счёт на предоплату глазами клиента.
4. Финансы филиала: приход с комментарием «Предоплата ApiPay, счёт №…»,
   привязанный к визиту.

Телефон и имя клиента на скриншотах — тестовые.
