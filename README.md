# apipay-altegio-app

Интеграция Altegio ↔ ApiPay: автоматическое выставление счёта на предоплату
при записи клиента и отметка оплаты в Altegio после оплаты счёта.

Работает только в тестовом режиме: тестовый кабинет Altegio + песочница
ApiPay. Реальные деньги не списываются, оплата имитируется тестовым статусом.

## Что делает

1. Клиент записывается в Altegio на услугу.
2. Altegio присылает вебхук о создании записи.
3. Приложение берёт из записи телефон клиента, услугу и сумму.
4. Создаёт счёт в песочнице ApiPay и сохраняет связку
   `altegio_record_id ↔ apipay_invoice_id` в SQLite.
5. После оплаты ApiPay присылает вебхук `invoice.status_changed`.
6. Приложение проверяет подпись, находит запись по связке и отмечает
   предоплату в Altegio финансовой транзакцией (приход по кассе).

## Стек

Node.js 22+ (нужен встроенный `node:sqlite`), TypeScript, Fastify,
SQLite, Docker Compose, ngrok.

## Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

Общие для всего приложения:

| Переменная | Что это | Где взять |
|---|---|---|
| `PORT` | порт приложения | по умолчанию 3000 |
| `DB_PATH` | файл SQLite | по умолчанию `./data/app.sqlite` |
| `PUBLIC_BASE_URL` | публичный адрес приложения | домен, на котором оно живёт |
| `DEV_ENDPOINTS_TOKEN` | включает служебные `/dev`-адреса | придумать; пусто = выключены |
| `ALTEGIO_PARTNER_ID` | ID партнёра | кабинет разработчика Altegio |
| `ALTEGIO_PARTNER_TOKEN` | токен партнёра (общий для приложения) | там же |
| `ALTEGIO_APPLICATION_ID` | ID нашего приложения в маркетплейсе | адресная строка приложения в кабинете разработчика; пусто — любой uninstall выключает салон |
| `ALTEGIO_USER_TOKEN` | системный токен приложения | API Access приложения; под ним же подключаются салоны со страницы настройки |
| `APIPAY_WEBHOOK_SECRET` | секрет подписи вебхука ApiPay | настройки вебхука ApiPay; один на всё приложение |

Настройки конкретного салона нужны **только для первого запуска** — при старте
из них создаётся строка в таблице `tenants`, после чего источником правды
становится база:

| Переменная | Что это | Где взять |
|---|---|---|
| `APIPAY_API_KEY` | ключ ApiPay салона | настройки организации ApiPay |
| `ALTEGIO_COMPANY_ID` | ID компании | `GET /companies?my=1` |
| `ALTEGIO_ACCOUNT_ID` | касса для зачисления | `GET /accounts/{company_id}` |
| `ALTEGIO_EXPENSE_ID` | статья прихода | `5` — Service payments |

Токен доступа к салону отдельно не задаётся: используется общий
`ALTEGIO_USER_TOKEN` — системный пользователь приложения добавляется в каждый
филиал, который его подключил.

Реальные значения в репозиторий не коммитятся: `.env` в `.gitignore`.

## Несколько салонов

Приложение обслуживает сколько угодно салонов через **одну пару адресов
вебхуков**. Разделение идёт по таблице `tenants`:

- вебхук Altegio несёт `company_id` — по нему находится салон;
- вебхук ApiPay подписан **общим секретом приложения** (`APIPAY_WEBHOOK_SECRET`);
  салон определяется по счёту: связку `счёт ↔ салон` мы завели сами, когда
  выставляли счёт. Салон ничего не настраивает на стороне ApiPay.

### Как подключается салон

1. Салон ставит приложение ApiPay в кабинете Altegio.
2. После согласия Altegio ведёт его на `/altegio/install`; приложение выдаёт
   одноразовую ссылку и перенаправляет на страницу настройки `/setup/<токен>`.
3. На странице салон указывает API-ключ ApiPay и номер кассы для зачисления
   предоплаты.
4. Приложение проверяет доступ к филиалу (через Altegio) и ключ (через ApiPay),
   после чего заводит салон в таблице `tenants`. Дальше всё работает само.

Ссылка живёт сутки и выдаётся только тому, кто прямо сейчас подключил
приложение: адрес `/setup` публичный, поэтому знать один только `company_id`
для настройки чужого салона недостаточно. Потерянную ссылку можно выписать
заново:

```bash
docker compose exec app node dist/tenant-cli.js setup-link --company 1354369
```

Когда салон отключает приложение, Altegio дёргает `/altegio/uninstall`, и салон
переводится в неактивные — его события больше не обрабатываются.

### Управление руками

Тот же салон можно завести командой, минуя страницу (не через веб, чтобы ключи
не ходили через публичный адрес). На сервере, из папки проекта:

```bash
docker compose exec app node dist/tenant-cli.js list
```

```bash
docker compose exec app node dist/tenant-cli.js add --company 1354369 --user-token <token> --account 2747575 --apipay-key <key> --apipay-secret <secret> --title "Салон"
```

```bash
docker compose exec app node dist/tenant-cli.js disable --company 1354369
```

Отключение приложения в Altegio выключает салон автоматически. Обратного
сигнала Altegio не присылает, поэтому после повторного подключения салон
включается командой:

```bash
docker compose exec app node dist/tenant-cli.js enable --company 1354369
```

Если салон поставил приложение в Altegio, но у нас ещё не настроен, его события
пропускаются, а сам салон попадает в список ожидающих:

```bash
docker compose exec app node dist/tenant-cli.js pending
```

Локально при разработке то же самое через `npm run tenant -- list`.

Повторный `add` с тем же `--company` обновляет существующий салон, а не заводит второй.

## ngrok

Вебхуки приходят снаружи, поэтому локальное приложение нужно открыть в интернет.

```bash
ngrok config add-authtoken <ваш токен>
```

```bash
ngrok http 3000
```

Окно не закрывать: на бесплатном тарифе адрес меняется при каждом
перезапуске, и вебхуки придётся прописывать заново. Входящие запросы
видны на `http://127.0.0.1:4040`.

## Настройка вебхуков

Оба адреса задаются один раз на всё приложение, а не для каждого салона:

- **ApiPay**, настройки вебхука → `https://<домен>/webhooks/apipay`
- **Altegio**, настройки приложения → `https://<домен>/webhooks/altegio`

Локально вместо домена берётся публичный URL из ngrok.

## Полный тест: от записи до подтверждения предоплаты

1. Создать запись в Altegio на услугу с ненулевой стоимостью и клиентом
   с телефоном.
2. Дождаться вебхука Altegio. Без вебхука сценарий можно запустить руками —
   для этого в `.env` должен быть задан `DEV_ENDPOINTS_TOKEN`:

   ```bash
   curl -X POST -H "X-Dev-Token: $DEV_ENDPOINTS_TOKEN" http://127.0.0.1:3000/dev/records/<record_id>/invoice
   ```

   Если подключено несколько салонов, добавьте `?company=<altegio_company_id>`.
   В ответе будет `apipay_invoice_id`.
3. Имитировать оплату в песочнице ApiPay:

   ```bash
   curl -X POST https://api.apipay.kz/api/v1/invoices/<invoice_id>/simulate-status -H "X-API-Key: $APIPAY_API_KEY" -H "Content-Type: application/json" -d '{"status":"paid"}'
   ```
4. ApiPay пришлёт `invoice.status_changed` на `/webhooks/apipay`.
5. Проверить результат в Altegio: в финансах компании появится приход
   на сумму записи с комментарием `Предоплата ApiPay, счёт №<invoice_id>`.

## Ограничения

- Только песочница ApiPay и тестовый кабинет Altegio.
- Номер кассы салон вводит руками. Altegio не даёт приложениям маркетплейса
  читать финансы филиала (`GET /accounts/{company_id}` → «No rights to manage
  the location») даже при полностью выданных правах Finance, а `account_id`
  при проведении прихода обязателен. Код подставит кассу сам, как только
  доступ появится.
- Предоплата отмечается финансовой транзакцией (приход по кассе).
  Флаги `prepaid` / `prepaid_confirmed` в самой записи не выставляются:
  у сотрудников тестовой компании стоит `prepaid = "forbidden"`.
- Частичная предоплата не поддерживается: счёт выставляется на полную
  стоимость услуг записи.
- Бесплатный ngrok меняет адрес при перезапуске.
